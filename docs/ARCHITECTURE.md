# TIMELINER — Architecture (v0.1, target for Phase 1)

Stack is fixed in `PLAN.md`. This file says how the pieces fit. UI look: `DESIGN.md`. Why the game rules exist: `RESEARCH.md`.

## 1. Big picture

```
┌──────────── UI: src/app (routes) + src/features (components) ────────────┐
│  Timeline · Focus · Review · Entry sheet · Settings                       │
└──────────▲───────────────────────────────────────────┬────────────────────┘
           │ live queries                              │ user intents
┌──────────┴──────────────┐            ┌───────────────▼──────────────────────┐
│ src/db                  │◄───writes──│ src/features/*/actions.ts            │
│ Drizzle + expo-sqlite   │            │ asks core what to do, writes the db, │
│ schema · migrations     │            │ schedules notifications              │
└─────────────────────────┘            └───────────────┬──────────────────────┘
                                                       │ pure function calls
                                       ┌───────────────▼──────────────────────┐
                                       │ src/core — pure TypeScript + Jest    │
                                       │ time/ · timeline/ · entries/ · game/ │
                                       └──────────────────────────────────────┘
```

**Godot mapping:** `core` = autoload scripts with rules and no nodes; `db` = the save file; `features` = scenes; `actions` = the functions your signals call.

**Rules**
- `core` imports nothing from React, Expo or `db`. Same input → same output. Time is always passed in (`now` is a parameter), so tests can freeze it.
- UI never calculates XP, streaks or timeline positions itself. It calls `core`.
- Store facts, derive the rest. "Active", "skipped", progress %, level and streak are computed, never saved.

## 3. Data model (expo-sqlite + Drizzle)

All times are **epoch milliseconds (UTC) as integers**. Entries that mean "a whole day / week / month / year" also keep the IANA time zone they were made in, so "November" stays November if you travel.

| Table | Columns | Notes |
|---|---|---|
| `layers` | `id`, `name`, `color`, `icon`, `sort`, `visible`, `createdAt`, `updatedAt` | A lane on the timeline (Work, Study, Health…). |
| `entries` | `id`, `layerId`, `kind` (`task` \| `todo` \| `note` \| `reminder`), `title`, `body?`, `startAt`, `endAt?`, `granularity` (`moment` \| `minute` \| `hour` \| `day` \| `week` \| `month` \| `year`), `tz`, `status` (`planned` \| `done` \| `cancelled`), `doneAt?`, `remindOffsetsMin` (JSON int[]), `treat?`, `createdAt`, `updatedAt` | Tasks have `endAt` (a time block). Todos, notes and reminders are points (`endAt` null). A month goal = task with `granularity: month`, start/end at month edges. |
| `focus_sessions` | `id`, `entryId`, `startedAt`, `endedAt?`, `pausedMs`, `outcome?` (`done` \| `stopped`) | Actual time for planned-vs-actual. |
| `xp_events` | `id`, `entryId?`, `reason` (`complete` \| `plan_ahead` \| `calibration` \| `break` \| `review`), `amount`, `at` | Append-only ledger. Level and totals are sums. Undo = delete the row. |
| `day_logs` | `day` (local `YYYY-MM-DD`), `reviewedAt?`, `freezeUsed` | Streak and review bookkeeping. |

- **IDs are UUID strings** (`expo-crypto` `randomUUID`), so rows made offline on two devices can merge when sync arrives in Phase 2.
- **Index** `entries(startAt)` and `entries(layerId, startAt)`.
- **Visible-range query uses overlap, not start:** `startAt < :viewEnd AND coalesce(endAt, startAt) > :viewStart`. A year goal must still show when you are zoomed into one hour inside it.
- Recurring entries are **not** in v0.1. Later: an RRULE string on the entry, expanded by `core`.

## 4. Timeline engine (the heart)

### 4.1 One continuous axis
There is no separate day view or week view. There is one infinite time axis, and zoom only changes how much time fits on screen. Think of a Godot `Camera2D` over a world whose x coordinate *is* time.

```ts
type Direction = 'down' | 'up' | 'right' | 'left';
type Viewport = {
  anchorTime: number;   // the time shown at anchorFrac
  anchorFrac: number;   // where "now" sits along the axis, 0..1 (default 0.3)
  span: number;         // ms visible along the main axis
  direction: Direction;
  follow: boolean;      // true = anchorTime tracks now every frame
};
// position along the axis, 0..1 from the "past" end:
p(t) = anchorFrac + (t - anchorTime) / span
// down/right use p; up/left use 1 - p; down/up map to y, right/left to x
```

- **follow = true:** `anchorTime = now` every frame, so the timeline flows past a fixed now-line like a clock.
- Dragging sets `follow = false`; the "Now" button sets it back.

### 4.2 Zoom ladder (semantic zoom)

| Scale | Visible span | Minor tick | Major tick (label) | Tap snaps to | Default task length |
|---|---|---|---|---|---|
| Sec | 40 s | 1 s | 5 s ("2:32:05 PM") | 1 s | 1 min |
| Min | 30 min | 1 min | 5 min ("2:35 PM") | 1 min | 25 min |
| Hour | 9 h | 15 min | 1 h ("3 PM") | 15 min | 25 min |
| Day | 4 days | 6 h | day ("Fri 30") | 1 h | 1 h |
| Week | 6 weeks | day | week ("Nov 2") | day | 1 day |
| Month | 8 months | week | month ("Nov") | day | 1 week |
| Year | 6 years | month | year ("2027") | month | 1 month |

Chips jump between rungs; pinch changes `span` smoothly, and the tick rung switches when major ticks get closer than ~48 px.

How an entry is drawn depends on its length on screen (`timeline/layout.ts`):
- **Band:** longer than 1.2 × the visible span → thin strip on the lane edge, with title and % in the lane header (a month goal while looking at one hour).
- **Compact:** shorter than ~24 px → colored mark, no text (a day's tasks seen from year zoom).
- **Card:** everything else. Points (todo, note, reminder) are fixed-size pills.
- **Overlaps** in one lane split into sub-columns (greedy interval partitioning by start time).

### 4.3 Layers = lanes
Each layer is a lane running beside the time axis, like the git branches in reference image 2. The user shows, hides and reorders layers. With one layer visible, it looks like the classic centered spine of reference images 1 and 4.

### 4.4 Directions
Down (phone default), up, right (landscape, tablet, web) and left are one projection: swap axes and/or flip. A radial "clock" view (24 h dial) can come later as one more projection, with no change to data or game code.

### 4.5 Smooth 60 fps
- Motion (follow, drag, pinch) runs on the UI thread with **Reanimated shared values** (`anchorTime`, `span`) and **Gesture Handler**. React does not re-render every frame.
- Positions are measured from a **local origin** near the view, re-based when you scroll far. Epoch-ms numbers turned into pixels lose precision in the 32-bit floats used by native transforms. Same idea as Godot's floating origin.
- Tick labels and cards re-render only when the window crosses a tick or data changes (at most once a second at Sec zoom).
- Only entries overlapping the window (+ one screen of buffer) are queried and mounted.
- Start with plain Views. Move ticks and grid to `@shopify/react-native-skia` only if a low-end Android phone drops frames.

### 4.6 The live clock
`setInterval` is never the source of truth. Everything is derived from `Date.now()`: task progress = `(now − start) / (end − start)`, focus time left = `end − now`. Killing the app or locking the phone can't break a timer. Reanimated `useFrameCallback` moves the now-line; a 1 s React tick updates the text. With "reduce motion" on, the now-line steps once per second instead of flowing.

## 5. Game core (`src/core/game`)

Event-sourced: every reward is an `xp_events` row. Un-completing a task deletes its row, stats are sums, and sync later is append-only.

Starting values (constants in code, locked by tests, tuned from real use):

| Event | XP | Why (RESEARCH.md #) |
|---|---|---|
| Complete a task | 10 + 1 per 5 planned min (max +20) | 5 |
| Complete a todo / acknowledge a reminder / capture a note | 5 / 2 / 1 | 5, 6 |
| Planned ahead (made ≥ 1 h before its start) | +2, max 10 a day | 1 |
| Actual time within ±20 % of plan | +5 | 2 |
| Break block taken | same as a task | 8 |
| Daily review done | +5 | 6, 19 |

- **Level:** going from level n to n+1 costs `100 + 25 × (n − 1)` XP.
- **Streak:** a day counts when ≥ 1 planned task is done. 1 freeze earned per 7 streak days (max 2), used automatically on a missed day. Optional weekly-target mode (5 of 7 days).
- XP is never removed for a miss. Skipped tasks only show as grey gaps.

## 6. Notifications
- `expo-notifications`, local only.
- Reminders, task start and task end. During a focus block, only its end.
- iOS keeps at most 64 scheduled local notifications, so schedule a rolling window (next 48 h, ≤ 50 items) and refill when the app opens.
- Android exact timing may need the exact-alarm permission. Check the SDK 58 docs before building this slice.

## 7. State
No global store library.
- Saved data → Drizzle `useLiveQuery` (re-renders when a table changes).
- Viewport → Reanimated shared values in a `TimelineView` context.
- Screen-only state → `useState`.

Add a store only if passing props becomes painful.
